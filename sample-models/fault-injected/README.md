# Fault-Injected IFC Models

This folder contains the **126 faulted IFC variants** generated from the seven valid baseline models (M1–M7) for the fault-injection experiments in the thesis:

**7 models × 6 fault types × 3 injection rates = 126 files**

The negative control M8 is not fault-injected: with no property or quantity data, most faults could not manifest.

The variants are generated by [`../../scripts/fault_injection.py`](../../scripts/fault_injection.py) from the files in [`../baseline/`](../baseline/). They are derived inputs, not independent source models. The experiment tests whether the BIM Quality Index (BQI) responds to known defects detectably, monotonically and selectively (thesis Sections 3.5 and 4.2).

---

## File Naming

```text
<model>__F<n>-r<rate>-s42.ifc                   F1, F2, F3, F5   (84 files)
<model>__F<n>-r<rate>-s42_PIPELINE-B-ONLY.ifc   F4, F6           (42 files)
```

- `<model>` is the baseline file name, for example `IFC4-Building-Architecture`
- `r10`, `r25`, `r50` are the injection rates (10%, 25%, 50%)
- `s42` is the random seed

The `_PIPELINE-B-ONLY` suffix marks the F4 and F6 variants, which are designed to be given to Pipeline B only in the dual-file configuration. The same files are also run in the single-file configuration as controls.

## Fault Types

All reported results use the default **light** intensity. What each fault does in `fault_injection.py`:

| Fault | Operation on each target element (light intensity) | Targeted instrument |
|---|---|---|
| **F1** | Removes the first property named `IsExternal`, `LoadBearing`, `FireRating` or `GrossPlannedArea` | D1 |
| **F2** | Sets the first property with a value to UNSET (`$` in the STEP file) | D1 + D2 |
| **F3** | Removes the first quantity of the element's first quantity set | D3 |
| **F4** | Multiplies every quantity value (`VolumeValue`, `AreaValue`, `LengthValue`, `CountValue`, `WeightValue`, `TimeValue`) in all of the element's quantity sets by 1.10 | D4 |
| **F5** | Removes the element's first `IfcPropertySet` together with its `IfcRelDefinesByProperties` relation; quantity sets are not touched | D1 + D2 |
| **F6** | Removes the whole element with IfcOpenShell's `root.remove_product` | Element coverage |

With `--intensity heavy`, F1, F2 and F3 act on every matching field instead of the first; heavy mode was not used for the reported results.

F1, F2 and F3 act on the first matching field, which is not necessarily one the category's rule table checks. A fault can therefore be applied to an element without moving the targeted dimension; this is part of the rule-coverage limitation discussed in thesis Section 5.5.

## Target Selection

The eligible population is every element of these sixteen types:

```text
IfcWall  IfcWallStandardCase  IfcSlab  IfcSlabStandardCase
IfcBeam  IfcBeamStandardCase  IfcColumn  IfcColumnStandardCase
IfcRoof  IfcDoor  IfcWindow  IfcSpace
IfcStair  IfcStairFlight  IfcFooting  IfcPile
```

The first twelve carry explicit BQI rules; the last four are scored through the fallback rules. `IfcElementAssembly` is not eligible.

For each file, the script:

1. collects the eligible elements and sorts them by `GlobalId`;
2. sets the number of targets to `max(1, round(eligible × rate))`, using Python's `round`, which rounds halves to even; and
3. draws that many targets with `random.Random(42).sample`.

The rate therefore controls **how many** elements are faulted, not how deeply each one is changed.

## Configurations

| Configuration | Files used | Pipeline A reads | Pipeline B reads | Runs |
|---|---|---|---|---:|
| Single file | F1, F2, F3, F5 variants | Faulted file | Faulted file | 84 |
| Single file | F4, F6 variants | Faulted file | Faulted file | 42 |
| Dual file | F4, F6 variants | Baseline file | Faulted file | 42 |

Together with the 8 baseline runs, the campaign has **176** pipeline executions.

With a single file, both pipelines read the same perturbed values, so F4 cannot create a disagreement and the BQI is unchanged by construction. In the dual-file configuration the disagreement is real: D4 falls in all 21 F4 runs, and element coverage falls in all 21 F6 runs. In the workflow, the dual-file configuration is set with `project_file` (baseline) and `project_file_b` (faulted variant) in node 0.1 Config.

## Manifests

`fault_injection.py` writes a JSON manifest next to every variant (`<variant>.manifest.json`) with:

- source file, fault type, description and configuration note;
- injection rate, seed and intensity;
- numbers of eligible, targeted and changed elements; and
- every change made, with the element `GlobalId` and the old and new values where applicable.

The manifests are regenerated with the variants and are not committed. Thesis Annex IV reports the per-run SRCC testability and element coverage of the dual-file runs.

## Regenerating the Variants

From the repository root, with IfcOpenShell 0.8.5:

```bash
python scripts/fault_injection.py sample-models/baseline/IFC4-Building-Architecture.ifc --all --seed 42 --outdir faulted
```

All seven valid models, in bash:

```bash
for m in IFC4-Building-Architecture IFC43-Building-Architecture IFC4-Building-Structural \
         IFC43-Building-Structural IFC4-Infra-Bridge IFC43-Infra-Bridge IFC4-Infra-Road; do
  python scripts/fault_injection.py "sample-models/baseline/$m.ifc" --all --seed 42 --outdir faulted
done
```

or in Windows PowerShell:

```powershell
"IFC4-Building-Architecture","IFC43-Building-Architecture","IFC4-Building-Structural",
"IFC43-Building-Structural","IFC4-Infra-Bridge","IFC43-Infra-Bridge","IFC4-Infra-Road" |
  ForEach-Object { python scripts/fault_injection.py "sample-models/baseline/$_.ifc" --all --seed 42 --outdir faulted }
```

A single variant:

```bash
python scripts/fault_injection.py sample-models/baseline/IFC4-Building-Architecture.ifc --fault F1 --rate 0.25 --seed 42 --outdir faulted
```

### Reproducibility check

Regenerating all 126 variants from the baseline files with the commands above reproduces this folder:

- **All 105 F1–F5 files** are identical once Windows line endings and the STEP `FILE_NAME` header (which holds the generation time) are ignored.
- **The 21 F6 files** differ only in the owner-history record written when an element is removed (its timestamp and entity number) and in the order of references inside relationship sets, which IfcOpenShell does not keep stable between runs. The remaining entities and every `GlobalId` are the same.

## Important Notes

- Interpret each variant together with its baseline file, `fault_injection.py`, its manifest, and the workflow configuration that assigns it to the pipelines.
- The baseline files are never modified.
- Before a campaign, delete old `<file name>_ifc.xlsx` conversions next to the faulted files: Pipeline A reuses an existing conversion instead of converting again (see [`../../docs/ddc-adaptation-notes.md`](../../docs/ddc-adaptation-notes.md), Section 12.5).
- The files in this folder are identical in releases `v1.0.1` and `v1.0.2`; the thesis cites `v1.0.2`.
